# Repository map — what is where, and what touches the account

This is the hand-written map. Three other maps in this directory are generated
from the source and go stale the moment the code moves, so they are regenerated
by tools rather than edited:

| Map | Generated by | Answers |
|---|---|---|
| [FUNCTION_MAP.md](FUNCTION_MAP.md) | `narzedzia/mapa_funkcji.py` | every function, who calls it, what is dead |
| [IDENTITY_MAP.md](IDENTITY_MAP.md) | `narzedzia/mapa_tozsamosci.py` | every place the account's name, subject or voice physically enters |
| [CONFIGURATION_MAP.md](CONFIGURATION_MAP.md) | written, kept current by CI | what is a field and what is still prose |

This one answers a different question: **if you had to rebuild this bot, or
find the one file that decides some behaviour, where would you look.**

---

## 1. The shape in one paragraph

`run.py` is the only entry point. It walks a chain of stages defined in
`stages.py`, each stage a model call described by a prompt in `prompts/`. What
comes back passes deterministic gates (`gates.py`, patterns in `jezyki.py`)
before anything reaches the outside world through `browser.py`, which drives a
real Chrome. Everything the run learns is written to one SQLite file by
`db.py`. `config.py` holds every constant; `konfiguracja.py` lets a TOML file
override the ones that describe an account rather than a mechanism.

Five runs a day, started by systemd timers. A monthly spending ceiling is the
only hard stop.

## 4. Where the account enters

Four kinds of thing tie this bot to one account. They are separated on purpose,
because they are changed at different times and by different people.

**1. Fields you set once** — `agent-v2/konfiguracja.toml`, written by
`narzedzia/kreator.py`. Handle, brand, timezone, subject, language, editorial
angle, niche examples, sources, model per role, volumes, windows, ceilings.
29 fields. An unknown key is a hard error, and every value is validated on
load. Full list: `python narzedzia/kreator.py --pokaz`.

**2. Secrets** — `agent-v2/.env`. Three API keys and two switches. Gitignored.
Never written into the TOML, on purpose: a config file with secrets in it is a
config file nobody can share, and somebody always shares it.

**3. Your voice** — `agent-v2/prompts/styl/`. Empty here. See its README: the
corpus must be your own writing or writing you hold the rights to. The loader
refuses to run against an unpinned corpus and tells you the three commands.

**4. Prose that still needs a human** — the 24 briefs in `prompts/`. They are
written to be subject-independent: the subject, brand, language, editorial
angle and five lists of niche examples are injected at call time by
`stages._pola_wspolne()`. Where a brief needs a concrete example and you have
not supplied one, it tells the model to work the equivalent out for your
subject rather than showing it somebody else's. What remains genuinely
hand-written is the *method* — and that is the part worth keeping.

`docs/IDENTITY_MAP.md` lists every physical occurrence, classified as FIELD,
INJECTED, GENERATED, TEMPLATE or BY HAND.

## 6. Tests — 127 files, and what a skip means

No pytest. Each file runs standalone (`python agent-v2/tests/test_x.py`) and
exits non-zero on failure. That is deliberate: a test you can run alone is a
test you can read alone.

Three guards decide whether a test proves anything today:

- **`historia.py` — `wymaga_historii(*sha)`.** Some tests compare current code
  against a named past commit. This history begins at one commit, so those
  tests now skip, loudly, rather than failing. 20 of them.
- **`wlasna_konfiguracja.py` — `tylko_nasze(sprawdz)`.** Assertions about *our*
  numbers ("likes 10–16, was 12–20") are skipped once you have your own
  `konfiguracja.toml`, and the skip is printed with a dash instead of OK.
  A quietly passing assertion would be worse than a failing one.
- **`tests/platne/`** — the 9 that spend money. Never run by CI, never by the
  loop above.

Expect three failures on a fresh Windows checkout with no keys: `test_czas`
(needs SIGTERM), `test_zapora_platnych_wywolan` (needs a key present),
`test_dokumentacja_zywa` (needs the generated docs committed).

## 7. What is deliberately not in the repository

| Path | Why |
|---|---|
| `agent-v2/.env` | API keys |
| `agent-v2/data/` | the database, articles, logs — one installation's working state |
| `agent-v2/prompts/styl/*.txt` | the style corpus is yours to supply, and the one that used to be here was somebody else's published journalism |
| `agent-v2/prompts/styl/przypiecia.json` | pins describing *your* corpus |
| `agent-v2/konfiguracja.toml` | your account. `konfiguracja.example.toml` is tracked |
| `narzedzia/dawne-tozsamosci.txt` | the list of strings the audit hunts for. A list of things you do not want published cannot itself be published. `dawne-tozsamosci.example.txt` is tracked |

`python narzedzia/audyt.py --historia` checks both the tree and every commit.

## 8. Rebuilding from here

1. `python narzedzia/kreator.py` — account, subject, sources, models, keys,
   volumes.
2. Put your style corpus in `agent-v2/prompts/styl/`, then
   `python narzedzia/przypnij_styl.py --pokaz` and `--wybor`.
3. `python narzedzia/audyt.py` — should be all green.
4. Run the test suite. Three failures above are expected; anything else is real.
5. `docs/INSTALL.md` before you set `DRY_RUN=false`.
6. `docs/TROUBLESHOOTING.md` when something goes wrong; it is written from
   failures that actually happened.
